# 新規開発スタート用ひな形 v1.0

この文書は**新しいChatGPT開発プロジェクトを立ち上げる際**に使う。アプリ固有の仕様を事前に決めつけない。

## A. Humanが最初に伝えること

> 新しい開発を始めます。まず `Gima-Hub/AIriProject` の `docs/AI_DEVELOPMENT_RULES.md` を共通ルールとして参照してください。今回は以下を作りたいです。
>
> **作りたいもの：** （自由に説明）
>
> **いつ・どの端末で使うか：** （分かれば）
>
> **特に困っていること：** （分かれば）
>
> 最初から実装を始めないでください。実現方法と重要な懸念を提案し、必要な質問をまとめて仕様を相談してください。次に第1完成条件を作り、私が承認した後にロードマップを提示してください。ロードマップの承認後にWorkerへ実装を指示してください。通常報告は「現在地・今回の成果・次の作業・本筋判定」の4項目で簡潔にお願いします。

※リンク先が読めない、ツールがない場合は「参照未完了」と明示し、読まずに読んだと断言しない。

## B. GPTがHumanと合意して埋める「第1完成シート」

- **アプリ名（仮）：**
- **Humanの目的・日常の利用場面：**
- **対象端末・利用者：**
- **第1完成時にできること（必須機能）：**
- **検証可能な完成条件（実機／実データの条件を含む）：**
- **第1完成までは作らない機能：**
- **守るべきデータ・認証・配信上の安全条件：**
- **既存資産（コード・環境・ファイル）と再利用方針：**
- **Humanが承認した日・決定内容：**

## C. ロードマップひな形（第1完成シート承認後に作成）

| 工程 | 何が使えるようになるか | 必須の前提 | 完了の確認方法 | 後回しにすること |
| --- | --- | --- | --- | --- |
| 1 | （例ではなく案件固有に記載） | | | |
| 2 | | | | |
| 3 | | | | |

工程数は必要最小限とする。承認前に開発へ進めない。

## D. Workerに渡す前のGPTチェック

1. この作業で第1完成条件のどの未達を解消するか。
2. 既存の成果で代替できないか。
3. 安全に調査・修正・試験を同じ作業にまとめられるか。
4. 実データや本番変更など、別承認が必要な操作を含まないか。
5. 作業後にHumanが何を確認・利用できるか。

合意済み完成条件・ロードマップ・承認境界を、新規アプリのGitHubにも正式保存する。共通原本を案件専用の規則で勝手に上書きしない。

## E. 既存開発への適用

BlueTaxやカラダスキャンなど進行中の案件は、独自GitHubの最新正式方針とHuman決定を確認し、今ある機能を活用する。新規開発の手順を理由に過去の仕様策定・開発をやり直さない。
